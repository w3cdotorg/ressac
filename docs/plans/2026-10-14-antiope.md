# Ressac Antiope Theme (Sub-project 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Ressac.app a second, complete look, Antiope: French teletext of the 1980s, with three-digit page numbers stored in the core, Minitel keys, image mosaics and an optional CRT screen, switchable live from Settings.

**Architecture:**

- **Phases 1–2 (Rust).** Schema v3 adds `folder.page`, `feed.page` and the view `v_page`; the core assigns page numbers once and keeps them; the CLI gains `ressac page list` and `ressac page set`.
- **Phases 3–6 (Swift foundations).** A `Teletext/` module (palette, Bedstead font, cell fitting), the Appearance setting with a live root-view switch, one `GardenStatusStyle`, and the data layer reading page numbers.
- **Phases 7–13 (Swift Antiope).** `AntiopeRootView` sits beside `MainView` and shares `AppState`. It brings navigation logic (page entry, page directory, focus, keys), frame views (header, columns, Minitel bar), the special pages and search, the Antiope reader and mosaics, the garden pages and the CRT screen.
- **Phase 14.** Manual acceptance on the real database and the docs.

**Tech Stack:**

- **Rust:** as in sub-projects 1 and 2a (edition 2024, rusqlite 0.40.2 bundled, clap). No new crate.
- **Swift:**
  - Swift 6.4, SwiftUI, macOS 27, Xcode 27, `xcodegen`;
  - GRDB.swift `7.11.1`, Swift Testing, WebKit;
  - Core Text (glyph coverage), ImageIO and Core Graphics (mosaics).
- **Font:** Bedstead `3.261` (CC0), `bedstead.otf`.

**Spec:** `docs/specs/2026-10-14-antiope-design.md` (*the spec*). Earlier specs: `docs/specs/2026-10-10-core-and-garden-design.md` (*core spec*) and `docs/specs/2026-10-10-mac-app-design.md` (*app spec*). Crate and API findings are in `notes.md`.

## Review Focus

Inputs and conditions the spec implies but no feature test naturally hits. Each one has its test in the owning phase.

1. **A title with emoji, CJK or a combining accent in a column row:** the separators stay straight and the row is exactly N cells. Phase 3: `CellText` tests on `"Café 🎉 東京"`; phase 8: a row-width test in `EntryPageColumn`.
2. **Typing digits while the search prompt or another text field has focus:** the digits go to the field, never to page entry. Phase 7 router test with `KeyFocus.textInput`.
3. **A database migrated to v3 and then opened by the app at v2:** it shows "This database was created by a newer Ressac", already handled by `SchemaCheck.tooNew`. Phase 6 test: `check(at:)` on a v3 file with `knownSchemaVersion` 2 is `.tooNew(3)`, by injecting the known version.
4. **An `<img>` whose server answers HTML, 0 bytes, or 50 MB:** the `IMAGE` block shows, nothing hangs, memory stays bounded. Phase 11 handler tests with a stub `URLProtocol`.
5. **Switching Appearance while a refresh is running or the search prompt is open:** no crash, the run keeps going, the search text survives. Phase 4 test on `AppState` across a switch; phase 9 test that the prompt closes and `searchText` stays.

### Phase 1 (Rust, `crates/ressac-core/src/store/pages.rs`)

```rust
pub const RESERVED_PAGES: [u16; 8] = [100, 101, 102, 103, 800, 801, 802, 899];
pub const ASSIGNABLE: std::ops::RangeInclusive<u16> = 110..=799;

#[derive(Debug, Clone, Copy, PartialEq, Eq, serde::Serialize)]
#[serde(rename_all = "lowercase")]
pub enum PageKind { Folder, Feed, Reserved }

#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize)]
pub struct PageRow { pub page: u16, pub kind: PageKind, pub id: Option<i64>, pub title: String, pub parent_page: Option<u16> }

/// Gives a number to every folder and feed whose `page` is NULL; returns how many were assigned.
pub fn assign_missing(conn: &rusqlite::Connection) -> Result<usize>;
/// Reserved pages first (titles: "Index", "Unread", "Today", "Starred", "Needs triage", "All feeds", "Cemetery", "Guide"), then `v_page` ordered by page.
pub fn list(conn: &rusqlite::Connection) -> Result<Vec<PageRow>>;
/// Renumbers one folder or feed; `kind` must be Folder or Feed.
pub fn set(conn: &rusqlite::Connection, kind: PageKind, id: i64, page: u16) -> Result<()>;
```

New `Error` variants (in `error.rs`): `PageReserved(u16)`, `PageOutOfRange(u16)`, `PageTaken { page: u16 }`, `UnknownPageTarget { kind: &'static str, id: i64 }`. The CLI maps all four to exit `2`.

**Assignment algorithm** (one definition; tests pin each rule):

- *Display order inside a parent:* sort by `(position, rank, id)`, with rank 0 for folders and 1 for feeds. This is the same as the app's `SidebarNode.tree`.
- *Walk:* depth-first, pre-order (a folder before its contents).
- *Root folders:* the i-th root folder (0-based, in display order) gets `(i + 2) * 100` if `i < 6`.
- *Inside a root folder:* the descendants of a root folder whose page is a hundred in `200...700` take the next free number in `page+1 ... page+99`.
- *Feeds without a folder:* the next free number in `110...199`.
- *Everything else:* a seventh root onwards, a full hundred, or a descendant of a root without a hundred page takes the lowest free number in `110...799` that is neither reserved nor a multiple of 100.
- *Existing numbers:* never changed; a buried or merged feed keeps its number. `assign_missing` only touches NULL pages.
- *One number space:* "free" means unused by any folder **and** any feed.

**Hooks:**
- `assign_missing` runs inside the v3 migration (after the SQL, like the FTS backfill) and at the end of the import transaction in `store/feeds.rs`. No transaction in `store/decisions.rs` inserts a feed (they only update), so it needs no hook.

**Schema** `schema/0003_pages.sql`:

```sql
ALTER TABLE folder ADD COLUMN page INTEGER;
ALTER TABLE feed ADD COLUMN page INTEGER;
CREATE UNIQUE INDEX folder_page ON folder(page);
CREATE UNIQUE INDEX feed_page ON feed(page);
CREATE VIEW v_page AS
  SELECT f.page, 'folder' AS kind, f.id AS ref_id, f.name AS title,
         (SELECT p.page FROM folder p WHERE p.id = f.parent_id) AS parent_page
  FROM folder f WHERE f.page IS NOT NULL
  UNION ALL
  SELECT d.page, 'feed', d.id, d.title,
         (SELECT p.page FROM folder p WHERE p.id = d.folder_id)
  FROM feed d WHERE d.page IS NOT NULL;
```
