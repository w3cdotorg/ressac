# Ressac macOS App (Sub-project 2a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `Ressac.app`, a native SwiftUI reader with three-column reading, full-text search, full-article extraction and the Garden as a sidebar destination, on top of schema v2 and new non-interactive `ressac` subcommands.

**Architecture:**

- **Phases 1–5 (Rust).** They extend the core and the CLI: schema v2, the backlog rule, FTS upkeep, `needs_triage` persistence, subset fetch, full-article extraction (`dom_smoothie`), and the garden subcommands.
- **Phases 6–13 (Swift).** They build the app in `apps/macos/`. It reads the shared SQLite database through GRDB, writes only `entry.read_at`, `entry.starred_at` and `feed.prefer_full_text`, and runs the bundled `ressac` binary for everything else, parsing its NDJSON events.

**Tech Stack:**

- **Rust:** as in sub-project 1, plus `dom_smoothie 0.18.2`.
- **Swift:**
  - Swift 6.4, SwiftUI, macOS 27, Xcode 27;
  - `xcodegen` (installed at `/opt/homebrew/bin/xcodegen`);
  - GRDB.swift `7.11.1` (SwiftPM);
  - Swift Testing;
  - WebKit (`WKWebView`).

**Spec:** `docs/specs/2026-10-10-mac-app-design.md`. Sub-project 1's spec, `docs/specs/2026-10-10-core-and-garden-design.md`, is the *core spec*. Crate API findings are in `notes.md`.

## Review Focus

Input classes the spec implies but no task would test by default. Each is pinned to a test in the owning task:

1. **Entries with no `url`, no `title` and only `summary_html`** must list ("Untitled"), render and be searchable. `extract` on them exits `2` with "This entry has no link.". Tests: Phase 4 `extract_without_url_is_a_usage_error`, Phase 9 `untitled_entry_shows_placeholder_title`.
2. **The app and the terminal writing at the same time** (a terminal `ressac fetch` while the app marks entries read) must not lose a read mark or crash. The busy timeout (5 s) applies, and a failed write reverts with a banner. Test: Phase 7 `concurrent_writer_does_not_lose_read_marks`, with a second connection holding a write transaction for 1 s.
3. **Hostile feed HTML** (`<script>`, `<iframe>`, `on*=` attributes, `javascript:` links, `<meta http-equiv=refresh>`, `<base href>`) must be inert in the reader. Test: Phase 10 `sanitizer_strips_active_content`.
4. **A database at schema v1 created by sub-project 1** must open in the app through `ressac migrate`. Its existing entries stay unread, and every entry has an FTS row afterwards. Tests: Phase 2 `migration_from_v1_backfills_fts_and_keeps_read_state`, Phase 7 `opening_v1_database_requests_migration`.
5. **A subprocess that prints a non-JSON line, a partial last line, or dies with a signal** must not crash the app. Unknown lines are logged and skipped, and a signal death becomes a failed run with a banner. Test: Phase 8 `runner_survives_garbage_and_signals` (stub executable).

## Interfaces at a glance

Phase files restate the ones they use. These names and shapes are fixed.

### Rust (ressac-core)

- **`extract` (Phase 1):**
  - `pub struct Article { pub html: String, pub title: Option<String>, pub byline: Option<String>, pub text: String }`;
  - `pub enum ExtractError { NoContent, LoginWall, Challenge, Fetch(ErrorKind) }` with `pub fn sentence(&self) -> String`. The texts are: "No article text found.", "The page is behind a login.", "Anti-bot challenge page.", `format!("{}.", kind.label())`, for example "HTTP 404.";
  - `pub fn extract_article(html: &str, url: &str) -> Result<Article, ExtractError>`, which is pure.
- **`text` helper (Phase 2), in `store/reading.rs`:** `pub fn plain_text(html: &str) -> String`. It strips tags with `scraper`, collapses whitespace and decodes entities.
- **`store` (Phase 2):**
  - `SCHEMA_VERSION = 2`; `MIGRATIONS` gains `(2, include_str!("../../../../schema/0002_reading.sql"))`, plus a Rust backfill step for FTS after migration 2;
  - `Store::save_fulltext(&self, entry_id: i64, outcome: &Result<Article, ExtractError>, now: DateTime<Utc>) -> Result<()>`. It also refreshes `entry_fts.body` when `Ok`;
  - `Store::fulltext(&self, entry_id: i64) -> Result<Option<FulltextRow>>`, where `pub struct FulltextRow { pub fetched_at: DateTime<Utc>, pub html: Option<String>, pub title: Option<String>, pub byline: Option<String>, pub error: Option<String> }`;
  - `Store::prefer_full_text(&self, feed_id: FeedId) -> Result<bool>` and `Store::set_prefer_full_text(&self, feed_id: FeedId, on: bool) -> Result<()>`, the latter used by tests, since the app writes it directly;
  - `Store::entry_for_extract(&self, entry_id: i64) -> Result<Option<(FeedId, Option<String>)>>`, returning the feed and the URL;
  - `Store::entries_needing_fulltext(&self, feed_id: FeedId, since: DateTime<Utc>, limit: usize) -> Result<Vec<(i64, String)>>`, returning entry ids and URLs fetched in this run that have no `entry_fulltext` row.
  - The backlog rule and the FTS upkeep live inside the existing entry-upsert path in `store/fetch.rs`. Their signatures are unchanged.
- **`store` (Phase 3):**
  - `Store::save_triage(&self, flags: &HashMap<FeedId, bool>) -> Result<()>`, which writes `feed_health.needs_triage`;
  - `Store::feeds_in_folder(&self, folder_id: FolderId) -> Result<Vec<FeedId>>`, active feeds of the folder and its subfolders, recursively.
- **`garden` (Phase 3):**
  - `pub fn recompute_triage(store: &Store) -> Result<()>`, built from `load_rows` and `GardenRow::needs_triage`;
  - `decide`, `undo` and `apply_safe_repairs` keep their signatures and call `recompute_triage` before returning.
- **`service` (Phases 3–4):**
  - `RefreshOptions { pub force: bool, pub only: Option<Vec<FeedId>> }`, which still derives `Default`;
  - `refresh` honours `only`, and `diagnose_all` calls `garden::recompute_triage` at its end;
  - `Ressac::extract_entry(&self, entry_id: i64, sink: &dyn EventSink) -> Result<ExtractOutcome>`, async, where `pub enum ExtractOutcome { Saved, Failed(String), NoUrl, UnknownEntry }`;
  - `Event` gains `Extracted { entry_id: i64, ok: bool, error: Option<String> }`, `Decided { feed_id: FeedId, decision: String }` and `Undone { feed_id: Option<FeedId> }`. It is serialised with `#[serde(tag = "event", rename_all = "snake_case")]`, so the tags are `"extracted"`, `"decided"` and `"undone"`;
  - existing tags, unchanged: `started`, `feed_done`, `network_unreachable`, `probing`, `wayback_done`, `finished`;
  - `Probing { what: "full articles", total }` precedes the full-text pass of a refresh.

### Schema v2 (Phase 2): `schema/0002_reading.sql`

```sql
ALTER TABLE feed ADD COLUMN prefer_full_text INTEGER NOT NULL DEFAULT 0;
ALTER TABLE feed_health ADD COLUMN needs_triage INTEGER NOT NULL DEFAULT 0;
CREATE TABLE entry_fulltext (
  entry_id   INTEGER PRIMARY KEY REFERENCES entry(id),
  fetched_at TEXT NOT NULL,
  html       TEXT,
  title      TEXT,
  byline     TEXT,
  error      TEXT,
  CHECK ((html IS NULL) <> (error IS NULL))
);
CREATE VIRTUAL TABLE entry_fts USING fts5(title, author, body, tokenize = 'unicode61 remove_diacritics 2');
CREATE INDEX entry_unread ON entry(feed_id) WHERE read_at IS NULL;
CREATE INDEX entry_starred ON entry(starred_at) WHERE starred_at IS NOT NULL;
CREATE VIEW v_entry AS
SELECT e.id AS entry_id, e.feed_id, f.title AS feed_title, f.folder_id,
       e.title, e.author, e.url, e.published_at,
       (e.read_at IS NOT NULL) AS is_read, (e.starred_at IS NOT NULL) AS is_starred,
       EXISTS (SELECT 1 FROM entry_fulltext t WHERE t.entry_id = e.id AND t.html IS NOT NULL) AS has_fulltext,
       e.summary_html, e.content_html
FROM entry e JOIN feed f ON f.id = e.feed_id
WHERE f.state = 'active';
CREATE VIEW v_unread_count AS
SELECT f.id AS feed_id, COUNT(e.id) AS unread
FROM feed f LEFT JOIN entry e ON e.feed_id = f.id AND e.read_at IS NULL
WHERE f.state = 'active'
GROUP BY f.id;
CREATE VIEW v_garden_row AS
SELECT f.id AS feed_id, f.title, fp.path AS folder_path, f.state,
       h.status, h.reason, json_extract(h.evidence, '$.clue') AS clue,
       h.evidence, h.remarks, h.proposed_action, COALESCE(h.needs_triage, 0) AS needs_triage,
       (SELECT d.decision FROM garden_decision d WHERE d.feed_id = f.id ORDER BY d.id DESC LIMIT 1) AS last_decision,
       f.wayback_url, f.html_url, f.xml_url
FROM feed f
LEFT JOIN v_folder_path fp ON fp.folder_id = f.folder_id
LEFT JOIN feed_health h ON h.feed_id = f.id;
UPDATE schema_meta SET version = 2;
```

## Reconciliations (controller, after the phase files were written)

The phase files are authoritative where they refine the interfaces above:

- **Phase 1:** `ExtractError::sentence` capitalises the label (`"Response too large."`). `MIN_ARTICLE_CHARS = 250`. A login wall is a password `<input>` on a page with fewer than 250 extracted characters.
- **Phase 2:**
  - `save_fulltext` never lets a failure overwrite a stored article;
  - `entries_needing_fulltext` treats any `entry_fulltext` row, including an error, as already tried, so only an explicit `extract` retries;
  - Phase 2 regenerates `tests/fixtures/contract.sqlite` at v2, and Phase 5 enriches it.
- **Phase 3:**
  - `RefreshOptions` loses `Copy`;
  - Phase 3 also edits `crates/ressac/src/main.rs` (`RefreshOptions { force, only: None }`);
  - `only` does not imply `force`; the CLI sets `force` for `--feed` and `--folder`.
- **Phase 4:**
  - `FULLTEXT_PER_FEED_PER_RUN` and `FULL_ARTICLES` are public;
  - an HTTP 401 on an article page maps to `LoginWall`;
  - Phase 4 touches `output.rs`, because the sink matches `Event` exhaustively.
- **Phase 5:**
  - `garden decide <buried> keep` restores the feed (the Cemetery's `k`); `repair` and `bury` on a buried feed exit `2`;
  - `--feed` and `--folder` conflict;
  - unknown ids exit `2`;
  - `migrate` runs `garden::recompute_triage`;
  - after decisions the CLI relies on `recompute_triage` inside the `garden` functions (no full re-diagnosis), as the TUI does.
- **Phase 7:**
  - after any `ressac` subprocess write, call `AppDatabase.notifyExternalChanges()` (GRDB does not see other processes' writes); `RunCoordinator` does it;
  - list rows carry no `contentHtml`; the reader uses `Queries.entry(id:)` and `state.selectedEntry`;
  - the observation alias is `LiveQuery`, never `Observation`.
- **Phase 8:**
  - `GardenDecision` lives in `Engine/RessacCLI.swift`;

- **Phase 9:**
  - it implements every `AppState` method, the garden and full-text ones included;

- **Phase 11:**
