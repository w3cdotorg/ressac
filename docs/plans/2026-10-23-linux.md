# Ressac on Linux (Sub-project 8) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ressac runs on Fedora KDE with its own database: first the terminal side with Linux file locations (Part A), then a Qt 6 / QML / Kirigami app linked to `ressac-core` that matches the Mac app feature for feature, CRT optional (Part B).

**Architecture:**

- **Part A (phases A1–A6).** `ressac_core::paths` becomes the single source of truth for every file location (macOS unchanged, XDG on Linux); the ticker keeps one state per database; small CLI fixes; README; a Fedora 44 dev container with the Linux gate; CI and release jobs.
- **Part B0.** The core gains what an in-process GUI needs: validations moved from the CLI, `today_start`, log initialisation, `EventSink: Send + Sync`, a schema probe.
- **Part B1–B10.** `crates/ressac-ui` (no Qt, tested anywhere) holds every model, state machine and pure renderer; `apps/linux` (`ressac-kde`, cxx-qt 0.10, Kirigami) holds bridges, QML and a small C++ shim. Phases follow the spec's order: skeleton, data layer, Native reading (then a VM checkpoint), Journal, garden, add feed / OPML / settings, Sea Chart, Antiope (then a VM checkpoint), CRT (optional), smoke test and recette.

**Tech Stack:** Rust edition 2024 (`rust-version = "1.99"`), cxx-qt / cxx-qt-lib / cxx-qt-build 0.10.0, Qt 6.11.2 (qtbase, qtdeclarative, qtwebengine, qtwebchannel), KF6 6.31 Kirigami and qqc2-desktop-style (runtime QML imports, not linked), lld, Fedora 44 aarch64. Existing crates as pinned in the root `Cargo.toml` (`scraper`, `image`, `tracing-*`, `rusqlite`, `tokio`, `wiremock`, `insta`).

**Spec:** `docs/specs/2026-10-23-linux-design.md` (*the spec*), with its companions `docs/specs/linux/mac-app-inventory.md` (*the inventory*: the parity checklist, its exact strings and numbers are binding), `docs/specs/linux/portability-audit.md` (*the audit*: call sites and core API), `docs/specs/linux/qt-spike-notes.md` and `docs/specs/linux/qt-spike/` (*the spike*: a working cxx-qt + Kirigami + WebEngine build to copy patterns from).

## Interfaces fixed by this plan

Phase files may add items but must not rename these.

- **`ressac_core::paths`** (A1): `pub enum Layout { MacOs, Xdg }` with `Layout::current()`; `pub struct Paths` with `Paths::from_env() -> Result<Paths, PathsError>`, `Paths::resolve(layout: Layout, env: &dyn Fn(&str) -> Option<OsString>) -> Result<Paths, PathsError>`, `database(&self) -> PathBuf`, `terminal_settings(&self) -> PathBuf`, `ticker_state(&self, db: &Path) -> PathBuf`, `log_dir(&self) -> PathBuf`, `cache_dir(&self) -> PathBuf`, `legacy_macos_database(&self) -> Option<PathBuf>`. `PathsError::NoHome`. `store::default_path() -> PathBuf` stays, delegating (falls back to the old behaviour only if `from_env` fails, with a logged error).
- **Core for the GUI** (B0): `ressac_core::garden::check_decision(store: &Store, feed: FeedId, decision: Decision) -> Result<(), Error>`; `ressac_core::service::check_subset(store: &Store, feeds: &[FeedId], folder: Option<FolderId>) -> Result<Vec<FeedId>, Error>`; `Ressac::open_with_feeds(db: &Path) -> Result<Option<Ressac>, Error>`; `ressac_core::clock::today_start<Tz: TimeZone>(now: DateTime<Tz>) -> DateTime<Utc>`; `ressac_core::logging::init(dir: &Path, verbose: bool) -> Option<WorkerGuard>`; `pub trait EventSink: Send + Sync`; `Store::probe(path: &Path) -> Result<SchemaState, Error>` with `pub enum SchemaState { Missing, Current, Older(u32), Newer(u32) }`. Refusals keep the CLI's sentences; the CLI's exit codes do not change.
- **`ressac-ui`** (B1 onwards): one module per area, named in the table (`sources`, `entries`, `runs`, `live`, `sanitize`, `article`, `keys`, `journal`, `garden`, `teletext`, `pages`, `mosaic`, plus `settings` for the key names and defaults). No Qt, no I/O except through `ressac-core`; time and time zone always passed in.
- **`ressac-kde`**: binary `ressac-kde`, QML module URI `org.w3cdotorg.ressac`, desktop id `org.w3cdotorg.ressac`, settings file `~/.config/ressac/ressac-kde.conf` (`QSettings("ressac", "ressac-kde")`), schemes `ressac:` (page, asset) and `ressac-mosaic:`, private drag MIME `application/x-ressac-feed`. Off Linux the crate compiles to a stub `main` that prints `ressac-kde runs on Linux only.` and exits 1, with every Qt dependency under `[target.'cfg(target_os = "linux")'.dependencies]`, so `cargo test --workspace` on the Mac needs no Qt.

## Global Constraints

- **Toolchain:** Rust edition `2024`, `rust-version = "1.99"`; pins in the root `[workspace.dependencies]`. New crates allowed: `cxx-qt`, `cxx-qt-lib`, `cxx-qt-build` `0.10.0` and `cxx` (Linux-only, `ressac-kde`); `tracing-subscriber` / `tracing-appender` move from `ressac` to `ressac-core` (B0b). Anything else needs a line in `notes.md` saying why.
- **Schema:** unchanged, v6. The app writes directly only `entry.read_at`, `entry.starred_at`, `feed.prefer_full_text`, through core functions; all SQLite access through `ressac-core` (never QtSql).
- **macOS frozen:** database `~/Library/Application Support/Ressac/ressac.sqlite`, logs `~/Library/Logs/Ressac/`, `terminal.json` and `ticker.json` next to the default database. No Swift file changes.
- **Linux paths:** database `$XDG_DATA_HOME/ressac/ressac.sqlite` (default `~/.local/share/ressac/`), `terminal.json` in `$XDG_CONFIG_HOME/ressac/`, ticker state and logs (`logs/`) in `$XDG_STATE_HOME/ressac/`, cache `$XDG_CACHE_HOME/ressac/`; relative `XDG_*` ignored; `--db` and `RESSAC_DB` win; no `HOME` → `PathsError::NoHome`.
- **Ticker state file:** default database → `ticker.json`; other databases → `ticker-<16 lowercase hex>.json` in the same directory, hash of the canonicalised database path (stable across `./x` vs absolute spellings).
- **Language:** UI strings in English and identical to the Mac app's (the inventory quotes them); Antiope's French labels (`SOMMAIRE`, `SUITE`, `RETOUR`, `GUIDE`, `RÉPÉTITION`, `CORRECTION`, `ANNULATION`, `FIN DE L'EDITION`) kept. `notes.md` in French, no em dash in French prose.
- **Shortcuts:** spec §7.2 table, verbatim. Menu mnemonics never use S, G, R.
- **Runs:** one long run at a time (fetch, import, edition build, add), a second refused with the Mac's sentence; short runs FIFO on one worker; `data_version` polled every 3 s while a Ressac window is active or the Sea Chart window is open and not minimised; progress reloads at most once per second.
- **Reader:** article JavaScript never runs; sanitiser guards 512 KB, depth 256, 2048 attributes, 1 s, 32-entry memo; CSP as the Mac page's (`mac-app-inventory.md` §2.7) adapted to the `ressac:` scheme.
- **Antiope:** Bedstead sizes 15/20/25/30 (default 20); 8 colours only, blue never on text; index 22 cells, entries 28, reader ≥ 24; pages as the inventory §5.3.
- **Settings keys:** `appearance`, `antiope.crt`, `reader.font` (`systemSans` default, `systemSerif`, `newsreader`, `atkinson`), `reader.size` (17, 12…28), `reader.size.antiope` (20), `reader.width` (`narrow`, `medium` default, `wide`, `forty`), `databasePath`, `chart.view`, `chart.ink`, `chart.animate`.
- **Time:** functions depending on now or the zone take them as parameters; Journal day starts at 04:00 local (`edition::day_start`).
- **Fedora:** 44 aarch64; dnf list from `qt-spike-notes.md` §1 (with `lld`); tests and runs as a non-root user; `QT_FORCE_STDERR_LOGGING=1` in the container.
- **Gates (every phase):**
  - Mac: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `node --test 'apps/macos/ChartTests/*.test.cjs'`.
  - Linux (from A4): `apps/linux/dev/dev.sh check` (the same four plus `ressac-kde` built and tested, as the container's non-root user). Before A4 exists, A1–A3 run the Mac gate only.
  - The Swift suite is not touched; B10 runs it once.
- **Step 0 rule:** before restructuring a file over 300 lines, remove its dead code in a separate commit (`store/mod.rs`, `service.rs`, `main.rs`, `cli.rs`, `commands/*.rs` are concerned).
- **Shell:** `export PATH="/opt/homebrew/bin:$HOME/.cargo/bin:$HOME/.orbstack/bin:$PATH"`.
- **Never:** touch the `fsvbuild`, `gotenberg` or `wc4*` containers; use the real database; use the network in tests (local `wiremock`); push, open a PR or merge without Clément; run `dnf install` on marghe's VM without his first go-ahead.

## Review Focus

1. **`XDG_*` set but empty or relative** (as some shells export them) → ignored, the default under `$HOME` is used, nothing written relative to the working directory. Test in A1 (`resolve` with `XDG_DATA_HOME=""` and `XDG_DATA_HOME="rel/dir"`).
2. **The same database named two ways** (`--db ./r.sqlite` from its folder, then the absolute path, or through a symlink) → one ticker state, no repeated entries. Test in A2.
3. **`ressac fetch` running in Konsole while the app marks entries read** → the write waits up to the busy timeout on the worker, the window never freezes, and a timeout reverts with "The database is busy (is `ressac` running in a terminal?)". Test in B2b (a second connection holding `BEGIN IMMEDIATE`).
4. **Hostile article HTML** (inline `<script>`, `onload=`, `javascript:` links, a 600 KB body, nesting 300 deep) → nothing executes, oversized or deep input falls back to plain text, the page still loads. Tests in B3a (sanitiser) and B3b (the app-script proof page also carries these).
5. **Suspend across 04:00, or a time-zone change while running** → the once-a-minute clock check builds the edition at the next tick after resume, and "Today" moves to the new midnight. Test in B4 (`journal::due_after(last_check, now, tz)` across a 6-hour jump and a zone change).
