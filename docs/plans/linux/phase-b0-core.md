**Decisions this phase pins:**

- **Refusal channels.** `check_decision`'s unknown feed is `Error::UnknownFeed(id)` ("No feed #N.", already that variant's text). Its two other refusals are `Error::Invalid(<the CLI's sentence>)`: "Feed #N is buried; only keep restores it." and "Nothing to repair for feed #N.". `Invalid` is already the garden's refusal channel (`record_decision`, `garden::decide`), and two new typed variants would need `error.rs`, a sixth file. `check_subset` refuses with `Error::UnknownFolder(id)` ("No folder #N.") and `Error::UnknownFeed(id)` ("No feed #N."). Check order unchanged: unknown, then buried, then nothing to repair; folder before feeds.
- **`check_subset` returns a list, never "no restriction".** Folder given: that folder's feeds, recursive, as `feeds_in_folder` returns them (`feeds` ignored; clap makes `--feed` and `--folder` conflict). Else every id in `feeds` must name a feed in any state (buried included: `refresh` skips buried feeds itself), and the result is `feeds` in the given order. Both empty: `Ok(vec![])`. The caller turns "no `--feed`, no `--folder`" into `only: None` itself; the CLI keeps doing that, so a folder with no feeds still fetches nothing, as today.
- **`open_with_feeds`** returns `Ok(None)` when `db` does not exist (nothing created) or when it holds no feed (after `Ressac::open` migrated it, as today). It prints nothing; the CLI keeps printing `No feeds yet: run "ressac import <file.opml>" first.` and applying its debug-only `RESSAC_ALLOW_PRIVATE_ARTICLES` hook. One visible difference, on a fatal path only: a failure of the feed count after a successful open now also carries the `cannot open database <path>` context (exit 1 either way; no test pins that text).
- **`logging::init`** is A1's `init_logging(dir, verbose)` moved whole: daily file `ressac.log.<date>` in `dir` (created), `RUST_LOG` or `info`, no ANSI in the file, a stderr layer when `verbose`, `None` (and no logging) when the directory cannot be created or written or a global subscriber is already set. The KDE app will call it with the same `Paths::log_dir()`.
- **`Store::probe`** never creates, migrates, backs up or changes the journal mode. It maps `Store::open_existing_query_only`: `Ok` → `Current`; `Err(DatabaseMissing)` → `Missing`; `Err(SchemaMismatch { found })` → `Older(found)` when `0 <= found < SCHEMA_VERSION`, `Newer(found)` when `found > SCHEMA_VERSION`, the `SchemaMismatch` error itself when `found < 0` (a hand-edited file); any other error (not a database, busy beyond 250 ms) is returned. A file without `schema_meta` (an empty file) is `Older(0)`: migrating creates the schema, as `Store::open` does.

    impl SkipsMidnight {
        fn offset_at_utc(utc: &NaiveDateTime) -> FixedOffset {
            let change = NaiveDate::from_ymd_opt(2026, 9, 6).unwrap().and_hms_opt(4, 0, 0).unwrap();
            FixedOffset::west_opt(if *utc < change { 4 * 3600 } else { 3 * 3600 }).unwrap()
